# Sprint 0 Plan: v0.0.1-v0.0.5

## Goal

Deliver the first playable slice for Causal Chain Elimination: MVP causal matching, solvable level data, core Canvas UI, tutorial onboarding, item usage, and a rewarded-ad adapter that can run in WeChat or mock mode.

## Scope By Version

### v0.0.1 Core MVP
- Core: CausalEngine direct match and BFS backtrack engine - Worker A/B done and integrated.
- Render/Input: BoardRenderer, TileAnimator, TouchHandler - Worker B done and integrated.
- UI: HUD top status bar - Worker C done in `src/ui/HUD.js`.

### v0.0.2 Board Generation
- Core: BoardGenerator, BoardValidator, Solver, Difficulty - Worker A done and tested.
- Data handoff: levels include generator seeds, fill rates, difficulties, and minimum step targets - Worker C done in `src/data/levels.json`.

### v0.0.3 Levels And Tutorial

### v0.0.4 UI Completion

- UI: win/fail result panel with stars, stats, and action buttons - Worker C done in `src/ui/ResultPanel.js`.
- Render effects/audio/screen integration - Worker B done and integrated.

### v0.0.5 Items And Ads
- Items: freeze, reveal, undo, shuffle inventory, per-level limits, adapter calls - Worker C done in `src/monetization/ItemManager.js`.
- Toolbar: bottom item toolbar with inventory, ad hints, and hit testing - Worker C done in `src/ui/Toolbar.js`.
- Ads: rewarded video wrapper with WeChat API support and mock success fallback - Worker C done in `src/monetization/AdManager.js`.

## Integration Notes

- UI classes use Canvas 2D only and expose `update`, `draw`, and `handleTap` style APIs.
- UI returns command objects instead of mutating game state directly.
- `ItemManager` expects game adapters with `freezeBacktrack`, `revealPath`, `undoLastMove`, and `shuffleBoard`.
- `MenuManager` level progress is local and can be replaced later by a dedicated progress service.
- All user-facing UI labels are referenced through `src/data/strings.json` keys.

## Risks

- Worker B must wire returned UI command objects into `game.js`, render, and input without changing Worker C files.
- Worker A/B engine method signatures may differ from ItemManager adapter names; add thin adapters in integration code if needed.
- Ad unit IDs are intentionally empty for development and must be configured before real WeChat ad testing.

## Integration Closeout

- Core, render/input, UI, level data, item, and ad mock modules are implemented for v0.0.1-v0.0.5.
- Local checks pass via `node tests\unit\core.test.mjs` and `game.js` bootstrap smoke test.
- Audio asset playback remains deferred because no sound assets exist yet.
