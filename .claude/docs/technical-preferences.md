## Coding Conventions

### Naming
- **Files**: PascalCase for classes/modules (`CausalEngine.js`), camelCase for utilities (`eventBus.js`)
- **Functions**: camelCase (`calculateBacktrack`, `renderBoard`)
- **Constants**: UPPER_SNAKE_CASE (`MAX_BOARD_WIDTH`, `TILE_SIZE`)
- **Classes**: PascalCase (`CausalEngine`, `BoardRenderer`)

### File Organization
- One class per file (single responsibility)
- Module pattern: each file exports one primary class/function
- No default exports — use named exports

### Code Style
- ES6+ features: `const`/`let`, arrow functions, template literals, destructuring
- No TypeScript (WeChat Mini Game constraint)
- No third-party libraries without explicit approval
- Comments only for non-obvious logic

### Performance Constraints
- BFS backtrack calculation: < 10ms (48-tile board)
- Animation frame budget: < 16ms (60 FPS)
- Memory: < 50 MB including level data
- Package size: < 1.5 MB main package

## WeChat Mini Game Specifics

### Entry Point
- `game.js` — game entry (required by WeChat)
- `game.json` — game configuration
- `project.config.json` — WeChat DevTools config

### APIs to Use
- `wx.createCanvas()` — canvas creation
- `wx.onTouchStart/Move/End` — touch input
- `wx.setStorageSync/getStorageSync` — local storage
- `wx.getFriendCloudStorage` — friend data
- `wx.shareAppMessage` — sharing
- `wx.createRewardedVideoAd` — rewarded video ads
- `wx.createInterstitialAd` — interstitial ads
- `wx.createBannerAd` — banner ads
- `wx.getSystemInfoSync` — device info

### Open Data Context
- Separate context for friend leaderboard rendering
- `wx.getOpenDataContext()` to access
- Communication via `postMessage`
